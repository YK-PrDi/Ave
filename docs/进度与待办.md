### ✅ 0. 字幕改造 —— 已验完（2026-08-18）

分两批：2026-08-17 提「一次少显示几个字 + 位置下移」，2026-08-18 追加
**「每块字数必须落在 6~10，不许出现单独的 2~3 字」**。四项验证全部跑过。

#### 改了什么

**① 一次只显示一小块**（原来整句挂满全程，ASR 单句实测中位 26 字）

新增 `subtitle.split_blocks()`。**与 `wrap_text()` 是两回事，别混**：
`wrap_text` 是同一张 PNG 内折行（多行**同时**可见），
`split_blocks` 切出来的块**先后**出现、各渲一张 PNG。旧折行逻辑一行未动。

块长**硬约束 6~10**（`MIN/MAX_CHARS_PER_BLOCK`）。
初版只设上限 8 + 「遇标点就断」，实测 213 块里 **58 块 ≤5 字**，
出现单独一屏的「接住,」，一屏太空 —— 用户 2026-08-18 否掉。

**算法必须是 DP，不准换回贪心**：贪心到句尾必撞死区 ——
剩 11 字时 6+5 会造 5 字块、整块出又超 10，只有回头把前面的块
改短才解得开。所以对整句所有合法切法求最优，代价函数只惩罚
不在标点收尾（标点收尾 0 / 词中断 30 / 标点甩到块首 60）。

**11 字以下有数学死区**：`n < 2*min` 时切两块必有一块不足下限，
这类整句直出，可能出现单块 11 字。仍是单行（折行阈值 14），显示无问题。

`pipeline.py:build_one()` 侧：块时长**按字数比例分摊**该句时长，
不等分（否则 6 字块和 10 字块停留一样久）；
末块直接收到句尾 `en`，避免浮点累加留缝隙。PNG 命名 `s{i}_{k}_{j}.png`。

**② 位置改成距底边 12.5%**（原 0.72 偏中间，与素材自带花字打架）

`subtitle.py` 新增 `BOTTOM_MARGIN = 0.125`，`VERTICAL_POS = 1 - 0.125 = 0.875`。
**用户确认的语义是「文本块中心」距底边 12.5%**，1280 高即块中心落 `y=1120`
（原来是 922）。`render_png()` 里 `top = h*VERTICAL_POS - total_h/2` 未改，
它本来就是按块中心算的。

#### 分主题依据（留档，换素材时照这个思路重建映射表）

**修复前现象**：21/39 条里有多个卖点在讲同一件事。#10、#20 甚至三个卖点都在讲接水。

**为什么是必需项不是优化项**：7 个文件夹是**同一产品的 7 个脚本版本**，

同一句话的四种说法。5 个卖点从 33 个片段里随机抽，撞上的概率自然高。

## 六、⚠ 接入宿主项目（羽刃）前必读：GPL 传染范围

### 传染分两层，性质完全不同

| | `ffmpeg.exe` | `av.libs/` 的 x264/x265 DLL |
|---|---|---|
| 怎么用 | `subprocess.run()` 起的**独立进程** | **加载进调用方进程**，同一地址空间 |
| 义务 | 提供对应源码 | 提供源码 **+ 可能牵连宿主项目的许可** |
| 状态 | ✅ 已解决（源码归档 + SHA256 已钉死） | 🔴 **未解决** |

第一层宿主项目照抄 `licenses/ffmpeg/SOURCE-OFFER.md` 即可。

原判断（8-16 记的）是「唯一的路是自行编译不带 x264/x265 的 PyAV，
成本远高于收益」。**那个结论在内部用的前提下成立，前提变了要重算。**

**已实测的部分**：`transcribe()` 接受 numpy waveform，不只是文件路径。
用随包 `ffmpeg.exe` 解成 16k 单声道 f32le 自己喂进去，与 PyAV 的
`decode_audio` 对比同一片段（2026-08-17 实测）：

| | 结果 |
|---|---|
| 样本数 | 65024 vs 65024，**完全相同** |
| 相关系数 | **1.0** |
| 识别文本 | **逐字相同** |
| VAD 语音占比 | 1.0000 vs 1.0000 |
| 差异 | PyAV 做了增益归一化（RMS 0.105 vs 0.149），波形形状一致 |

**但有个卡点，没验通**：`av` 是在 `faster_whisper/__init__.py` **第 1 行**

## 九、⚠ 语速统一改造（2026-08-26 用户实听反馈后重做）

用户听完 39 条后给了三条反馈，**指向同一个根因，是第八节倍速方案的设计错误**。

### 用户原话与实测根因

| 反馈 | 实测根因 |
|---|---|
| 「前 3s 口播速率太慢，听得出是 AI 补的」 | AI 段语速被压到 **2.53 字/秒** |
| 「有的念得快有的慢，倍速不要相差太大」 | 真人段 **3.84~10.64 字/秒**（差 2.8 倍） |
| 「13s 拿哪块，字幕是哪哪块」 | ASR 同音误识，字幕忠实照搬 |

**根因在 `tts.synth_fit()`**（第 202~203 行）：

```python
want = natural / target_dur                      # 文本短 → want < 1.0
speed = min(max(want, SPEED_MIN), SPEED_MAX)      # 就真的放慢合成
```

**每段各自算语速去贴合自己的时长**。文本相对时长越短，语速被压得越慢。
AI 段 `want ≈ 0.43` 直接夹到 `SPEED_MIN=0.8`，所以「明显听得出是补的」。

叠加第二个错：`vision.CHARS_PER_SEC` 抄了 `tts.StubBackend` 的 `0.22 s/字` ——
**那是产静音占位的假值**，不是真人语速。实测真人中位 **5.91 字/秒**（0.169 s/字）。
上限算成 21 字，模型只写 13 字（62%），TTS 就得放慢填满窗口。

### 新方案：固定语速 + 画面逐段适配（用户 2026-08-26 定）

> 用户原话：「固定语速，按照 ai 补充的口播文案决定，出现口播文案结束仍有画面
> 出现的留白情况，让 ai 自动调节画面倍速自动适配文案」

配音按 `tts.FIXED_SPEED = 1.0` 合成 → 量出真实时长 →
**画面倍速 = 源片时长 / 配音时长**，逐段不同。

- `tts.synth_fixed()` 新增，不做任何 atempo/apad，只管固定语速合成并报时长
- `tts.synth_fit()` 标记废弃（保留怕别处还在调）
- `render.build_filter(clip_speeds=[...])` 收逐段倍速列表，逐路 `setpts=PTS/cs`
- 倍速夹在 `CLIP_SPEED_MIN/MAX = 0.9/1.8`，超出才回落压配音/补静音
- `vision.CHARS_PER_SEC` 改成实测 **5.91**，并新增 `char_range_for()` 给**下限**
  （`MIN_CHARS_RATIO = 0.85`）—— 只给上限时模型只写 62%

**⚠ 两个分支的方向极易搞反，我第一版就写反了**：
`raw = dur / voice_dur`，`cs` 是把它夹进 [0.9, 1.8] 的结果。
- `raw < 0.9`（配音比画面长）→ cs 被**抬到** 0.9，故 **cs > raw** → 压配音
- `raw > 1.8`（配音比画面短）→ cs 被**压到** 1.8，故 **cs < raw** → 补静音

写反的现象是实测报「补静音失败」（`pad_to` 的 gap 是负数）。推导已写进代码注释。

### 实测结果（全量 39 条，`--seed 7`）

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 出片 | 39/39 | **39/39 零失败** |
| 用时 | 718s | **562s**（快 28%，配音不再二次变速合成） |
| 压配音比例 | 12%~24%，均值 **17%** | 1%~17%，均值 **7.4%** |
| 补静音 | 8 条 | **0 条**（画面去适配了） |
| 超 30% | 0 | 0 |

**逐段倍速分布**（55 段按固定语速估算）：理想倍速 0.67~1.85、中位 **1.25**；
夹紧后 **47/55 段（85%）落在区间内**，画面完美适配、语速纯净不做任何变速；
7 段要压配音、1 段要补静音。

AI 文案字数从 13 字变成 **24~31 字**，落进/略超新区间。
超上限反而是好事 —— 画面会加速适配，而写不够才会导致配音放慢。

### 8.1 全局倍速 1.2x（前端可调）

口播本来就是按画面时长合成的，所以画面变短，配音自动说得更紧。

改法：`config.PLAYBACK_SPEED = 1.2`；`pipeline.build_one()` 引入
`eff = dur / speed`，**时间轴基准全部换成 `eff`**（TTS 的 `target_dur`、
字幕窗口、`timeline +=`）；`render.build_filter()` 每路视频输入前插
`setpts=PTS/{speed}` 再 concat。CLI 加 `--speed`，界面加数字输入（0.5~2.0）。

**⚠️ 倍速在 concat 之前逐路做**，不是 concat 之后整体做。总长虽一样，
但逐路压缩才与 pipeline 侧按 `dur/speed` 逐段排的时间轴对齐。

**ASR 时间戳要同比压缩**：`s['start']/speed`。那是原速下测的，不除会错位。
AI 文案那条走单段伪 segment（`n==1` 分支），不受影响。

**实测（`--limit 2 --seed 7`，两个倍速各跑一遍）**：

| | 1.0x | 1.2x | 比值 | 期望 | 偏差 |
|---|---|---|---|---|---|
| 混剪_001 | 38.29s | 32.00s | 1.1966 | 31.91s | +0.09s |
| 混剪_002 | 36.29s | 30.33s | 1.1965 | 30.24s | +0.09s |

**回归保险**：`speed=1.0` 时 `build_filter()` 输出与改动前**三个用例字符串完全一致**
（改之前先存了基线再比对）。字幕位置量像素：块中心 y=1133，期望 1120，
偏差 13px < 半行高，与上次改字幕记录的 1121.5 同量级。

**语速上限够用，`tts.py` 一行未改**。`SPEED_MAX = 1.3`，1.2 倍速下所需语速
约 1.15~1.2 在上限内。提示从「配音比画面短」变成部分「配音比画面长 11~16%，
已加速压缩」—— 这是预期的，铁律 8 的行为（补静音不慢放）没变。

**⚠️ 抽帧时看到两行字幕别误判**。上面那行是**素材自带花字**
（源片就有，实测抽源片帧确认），我们的字幕在下面 12.5% 处。
字幕当初下移就是为了避开它。

### 8.2 无口播分镜用 AI 写口播（🟡 真模型未验）

**问题**：幻觉闸门把语音占比 <50% 的片段判为无口播，那些片段既没配音也没字幕
（实测 3 个：`7/随意摆放` 23%、`7/台面少接水` 17%、`7/通风悬挂` 0%），
还因为读不到 ASR 原文只能用文件名标签参与聚类。

新增 **`ave/vision.py`**（抽帧 + 调视觉模型，纯后端不碰缓存，形态照 `tts.py`）：
`extract_frames()` 在 `dur*(i+0.5)/n` 抽 3 帧、512 宽、`-ss` 放 `-i` **之后**
（精确 seek，避开首尾黑帧）；`ArkVisionBackend` 走方舟

（`RETRIES=3` + 指数退避）；`StubVisionBackend` 无 Key 时回落。

### 8.4 BGM 分两层（只做目录分层，不做密钥）

用户明确：**这次只落目录分层，密钥隔离等羽刃接入方案定了再做**。

| 层 | 路径 | 能否删 |
|---|---|---|
| 内置 | `_resource("bgm")`（打包落 `_internal/bgm`） | ❌ 界面拒绝并说明原因 |
| 自定义 | `%LOCALAPPDATA%\Ave\bgm` | ✅ |

`config.bgm_layers()` / `list_bgm()` 返回带 `'builtin'|'custom'` 标记的列表，
`pipeline.pick_bgm()` 合并两层随机挑。`BGM_EXTS` 从 pipeline 和 server 两处收拢到 config。

**⚠️ `bgm_layers()` 必须去重且标签不错位**。源码态两层可能解析到同一路径
（没建用户目录时 `BGM_DIR` 回落到应用目录），不去重那批曲子会被算两遍、
抽中概率翻倍。撞上时**保留 `builtin`** —— 宁可让界面拒绝删除，
也不能把随包授权的曲子当成用户自己加的删掉。

`launcher.py` 加 `--pick-files`（tkinter `askopenfilenames`，路径逐行打 stdout），
`server.py` 抽出 `_run_launcher()` 复用「走 `sys.executable`」那套（铁律 10）。
**走原生文件框不走 HTTP 上传**：浏览器拿不到真实路径，上传要引入
`python-multipart`（当前未装）。

**实测**：造 2 首内置层 + 原 7 首自定义层，300 次抽样命中 builtin 71 次
（期望 2/9=67，正常波动）；删内置层被拒并给出原因；删自定义层文件真消失；
路径穿越两条（`../../../evil.mp3`、`C:\Windows\win.ini`）都被挡住；
`--pick-files` 桩掉对话框后带空格和中文的路径逐行原样返回。
**用户现有 7 首自动算自定义层，无需迁移**。
