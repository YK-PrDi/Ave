## 二、待办（按建议顺序）

### 🔴 1. manifest bug —— 成品旁显示的组合明细是错的

**现象**：界面上 `混剪_001.mp4` 标着结尾 `6/给水一个出口`，实际这条是 `--seed 7` 渲的，
真实结尾是 `4/间接促单与行为提示`。

**根因**：`App.vue` 里 `seed` 默认 `null`，调 `/api/preview` 不传 seed，后端每次重新随机抽样。
`OutputList` 按序号把 `混剪_007.mp4` 对到「当前这次随机结果的第 7 条」，而那不是当初渲染的第 7 条。
实测 5 次调用出 4 个不同结尾。

**为什么之前没看出来**：钩子永远是对的 —— `build_combos` 按 `hook_groups` 顺序遍历、每组用满 3 次，
顺序确定；多数钩子组只有一个变体，`rng.choice` 每次返回同一片段。所以只有卖点和结尾在漂，伪装性强。

**修法**：渲染时把实际用的组合写 `.ave-manifest.json` 到输出目录，`/api/outputs` 读它返回真实构成。
选它而非「内存里存 job 记录」：这 39 条是 CLI 跑的，内存方案覆盖不到，且服务重启即失。

改动范围：`pipeline.py` 渲完一条追加记录 → `server.py` 的 `/api/outputs` 合并读取 →
`OutputList.vue` 改用返回里的真实字段。
旧成品无 manifest，界面显示「组合信息不可用」而不是猜。

**先修这个的理由**：修好后界面显示的才是每条真实构成，去重效果才能逐条点开核对。
否则是拿一个显示假数据的列表去验去重。

### 🔴 2. 组合去重 —— 54% 的成品有同主题卖点重复

**现象**：21/39 条里有多个卖点在讲同一件事。#10、#20 甚至三个卖点都在讲接水。

**为什么是必需项不是优化项**：7 个文件夹是**同一产品的 7 个脚本版本**，
几乎每个卖点在每个文件夹里都有近义孪生。ASR 原文对比：

```
1/分层悬空通风      湿的东西分开悬空,周围更容易通风
2/湿物分层悬空核心  湿物分开悬空,不再全挤成一团
5/分层展开通风机制  高低杆把抹布分层展开,湿物不挤在一起
6/分开挂            湿抹布分开挂,周围更容易通风
```

同一句话的四种说法。5 个卖点从 33 个片段里随机抽，撞上的概率自然高。

**根因**：`combo.py:213` 的 `rng.sample(point_groups, point_count)` 只保证
同一素材的两个变体不同时出现，不管语义。

**已定**：`4/主卖点机制纠正` 归「分层悬空通风」。
依据是 ASR 原文「两层杆把抹布错开挂，**湿物自然分开**」—— 落点是干燥，
不是「错层拿取」那组的不挡手（易用性）。

**⚠ 待用户定：主题内要不要加权**

| | 不加权 | 加权 |
|---|---|---|
| `7/稳定承重` 曝光 | 7 → **~21 次** | ~7 次 |
| `7/清洁的设计` 曝光 | 7 → **~21 次** | ~7 次 |
| 分层悬空通风每条 | ~7 → ~3 次 | ~5 次 |

不加权时那两个片段独占单成员主题，主题被抽中就必上（组内只有它），
半数以上视频会出现同一句话 —— 等于把「重复」换成「曝光失衡」。
加权则选主题时按成员数加权，片段级曝光大致均匀，代价是抽样函数多十行。**建议加权。**

**实现注意**：按 ASR 原文分主题而非文件名标签（标签是人写的概括，可能有偏差）。
`7/卖点3-通风悬挂-1` 无 ASR 文本（就是那个 0% 废片），需回落用标签。

```
  models\fw_medium\  cache\asr.json  bgm\
```

模型查找顺序：`%LOCALAPPDATA%\Ave\models\` → `exe同目录\models\`（共享盘手动拷也支持）→ 下载。

**已知 bug 待修**：`server.py` 的 `pick_dir()` 硬编码 `subprocess.run(["python","-c",...])`，
办公机没 Python，「选择文件夹」按钮必然失败。改走 `sys.executable`：
冻结态调 exe 加 `--pick-dir`，源码态调 `-m ave.launcher --pick-dir`。

**风险**：ctranslate2 是 PyInstaller 老大难（`.dll` 51.6MB 要落在包目录旁），首次构建大概率要调 spec。
分发包约 200-250MB（不含模型）。
