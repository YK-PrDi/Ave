## 上一轮做了什么（用户实听反馈驱动的返工）

用户听完 39 条后给了三条反馈，**推翻了我上一版的倍速方案**：

1. 「前 3s 口播太慢，听得出是 AI 补的」
2. 「有的念得快有的慢，倍速别差太大」
3. 「13s 拿哪块，字幕是哪哪块」

根因是 `tts.synth_fit()` **每段各自算语速去贴合自己的时长**
（实测真人 3.84~10.64 字/秒，AI 段 2.53）。已改成
**固定语速合成 + 画面逐段适配**（`tts.synth_fixed()` + `render(clip_speeds=[...])`）。

改造后：压配音比例从「12~24% 均值 17%」降到「1~17% 均值 7.4%」，
补静音从 8 条降到 0 条，55 段里 47 段（85%）画面完美适配、语速纯净。

另外用户澄清了 1.2 倍速的语义：**那是前端导出时的后处理**，
不是渲染参数。所以加了 `render.respeed()` + `POST /api/export`，
落 `导出_1.2x/` 子目录不覆盖原片，改倍速不用重渲（一条 1.4 秒 vs 重渲 9 分钟）。

细节全在 `docs/进度与待办.md` **第九节**，含所有实测数字和踩的坑。

```bash
import sys,json,os,importlib; sys.path.insert(0,'.')
sys.stdout.reconfigure(encoding='utf-8',errors='replace')
from ave import config; import ave.asr as asr; importlib.reload(asr)
p=config.ASR_CACHE; c=json.load(open(p,encoding='utf-8')); n=0
for k,v in c.items():
    for s in v.get('segments',[]):
        o=s.get('text',''); w=asr._apply_corrections(o)
        if w!=o: print(o,'->',w); s['text']=w; n+=1
if n: json.dump(c,open(p+'.tmp','w',encoding='utf-8'),ensure_ascii=False,indent=1); os.replace(p+'.tmp',p)
print('修正',n,'段')"
```
